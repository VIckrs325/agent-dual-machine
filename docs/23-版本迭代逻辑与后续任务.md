# 23 — 版本迭代逻辑（以及接下来该做什么）

> 2026-10-20 02:52 · 首次真实晋级 + 回滚已跑通

## 0. 三句话

1. **两条轨**：`bridge/`（稳定，在跑）+ `bridge-test/`（试验）。
2. **晋级只搬代码，不搬配置** —— 功能开关永远由你单独决定。
3. **安全网已验证**：晋级失败会自动还原；回滚也实测通过。

## 1. 功能分级（决定什么能进稳定版）

| 级别 | 含义 | 当前包含 |
| --- | --- | --- |
| **L0 核心** | 缺了机器人就不能用 | 私聊问答、单实例锁、消息去重、并发保护、会话落盘、自消息过滤 |
| **L1 已确认** | 实测稳定、日常在用 | 群聊接话窗口（`groupEngagement`）、人设「喵/～」、冷却与限流 |
| **L2 试验中** | 有已知 bug 或效果不稳 | 联网搜索（`search`）、群关系网与称呼（`relations`）、自然语言关系命令（`nl`） |
| **L3 未做** | 想法阶段 | 多查询改写、结果重排、长提示分块 |

**当前稳定版 = L0 + L1**（`search.enabled=false`、`relations.enabled=false`、`nl=false`），跟你"有 bug 的先别进稳定版"的判断一致。

## 2. 迭代循环（每一轮只推一个特性）

```
① 在 bridge-test 改
        ↓
② 门禁 1：node --check（语法）
   门禁 2：check-bridge-test-features.mjs（关键函数没丢）
        ↓
③ 影子观察（SHADOW=1，只记录不发送）
        ↓
④ 旁路验证：日志里看它"本来会说什么"，至少 20 条
        ↓
⑤ promote-bridge.sh
   自动：备份 → 覆盖 4 个代码文件 → 重启 → PID 级验证 OneBot → 失败即还原
        ↓
⑥ 观察 1~2 天 → 有问题 rollback-bridge.sh 一条命令退回
```

**关键约束**：一轮只上一个特性。两个一起上，出问题分不清是谁的锅。

---

## 3. 配置与代码分离（这是整套设计里最值钱的一条）

`promote-bridge.sh` 只搬：

```
qq-bridge.mjs   search.mjs   relations.mjs   relations-nl.mjs
```

**永远不动 `config.json`**。所以：

- 测试版开着搜索 → 晋级后稳定版的搜索**仍然是关的**
- 想让稳定版开某个功能 → 单独改 `bridge/config.json`
- 回滚只回代码，不会把你的配置改回去

实测确认：晋级后稳定版 `search.enabled` 仍为 `false`。

## 5. 首次真实晋级的实测记录

| 步骤 | 结果 |
| --- | --- |
| 第一次 promote | **失败并自动回滚** —— 脚本用 `sleep 3` + `journalctl --since 15s` 判断连接，journald 落盘延迟导致误判 |
| 定位 | 日志里其实 1 秒内就 `OneBot 已连接`，但脚本没等到 |
| 第二次修法 | 改成 15 次轮询（仍失败，因为 `is-active` 在循环开头 `break`） |
| 最终修法 | **以本次启动的 PID 为锚点**（`grep "node[$PID]"`），不依赖时间戳 —— 因为这台机器时钟会在 02:4x / 08:2x 之间跳 |
| 第三次 promote | ✅ 成功，快照 `stable-20261020-024912` |
| rollback 实测 | ✅ 退回 `stable-20261020-024832`，代码哈希回到 `fac5d5e` |
| 再 promote | ✅ 回到 `5f95dc0`，服务 `active` |

**结论：这套安全网是真的能用的**，不是纸面流程。
