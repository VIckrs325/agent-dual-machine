# 21 — 3B/4B 级别有 Qwen 的竞品吗？

> 2026-10-20 02:00 · 同一套六题、同一台机器（RTX2060 6GB）

## 0. 结论

**有竞品，但在中文 + 多步推理上，它们都打不过现役 `qwen3.5:4b`。**

| 模型 | 速度 | 六题得分 | 一句话 |
| --- | --- | --- | --- |
| **qwen3.5:4b（现役）** | 50.6 tok/s | **5/6** | 综合最强，工具可用 |
| **minicpm3:4b**（面壁） | 21.8 @8k / **28.5 @4k** | **4/6** | **唯一算对「九折」的**，中文语义最稳，但慢一半、KV 极重 |
| gemma3:4b（Google） | 64.2 | **3.5/6** | 竞品里最快，**没有工具调用** |
| qwen14b IQ2_M | 9.0 | 3/6 | 慢且不可靠（见 docs/20） |
| qwen2.5:3b | **93.0** | 2/6 | 快一倍，准确率掉一半 |
| llama3.2:3b（Meta） | 88.4 | **1/6** | 快，但中文推理基本不能用 |
| phi4-mini（微软） | 55.2 | **0~1/6** | 中文最差，代码的并列逻辑也错 |

## 1. 六题实测（题面与期望答案在 `scripts/quality-tests.mjs`）

| 题 | qwen3.5:4b | gemma3:4b | qwen2.5:3b | llama3.2:3b |
| --- | --- | --- | --- | --- |
| 算术：12瓶×3.5×8箱×9折（应 302.4） | ❌ 420 | ❌ 115.2 | ❌ **252** | ❌ **304** |
| 鸡兔同笼（应 鸡23 兔12） | ✅ | ✅ | ❌ 13/22 | ❌ 20/15 |
| 代码 most_common（并列取首个） | ✅ | ✅ | ✅ | ✅ |
| 摘要 ≤40 字 | ✅ | ⚠️ 41 字 | ✅ | ❌ 超字数且丢数字 |
| 自动化脚本（压缩 7 天前并**计数**） | ✅ | ❌ 用 `find *.log.*` 统计全部历史压缩文件 | ❌ `gzip --list --files0-from=-1` 不存在 | ❌ 「超过7天」写成「最近7天」且不计数 |
| 数据聚合降序 | ✅ | ✅ | ❌ 没排序 | ❌ 写了个读 `text.txt` 的脚本 |

**得分：4B 5/6、gemma3 3.5/6、qwen2.5:3b 2/6、llama3.2:3b 1/6。**

> gemma3:4b 另有两个硬伤：**没有原生工具调用**（`tool: no`，B 档直接排除）；冷启动要 **8.5 秒**（32k 上下文分配）。

## 2. 最有价值的一个发现：所有小模型都栽在「打九折」

三道不同家族的模型，算同一道题：

| 模型 | 答案 | 它实际算的是 |
| --- | --- | --- |
| qwen3.5:4b | 420 | 42 × 10（把 8 箱×0.9 当成 10？） |
| qwen2.5:3b | **252** | 42 × 8 × **0.75** ← 把「九折」当成七五折 |
| llama3.2:3b | 304 | 42 × 0.9 × 8 ≈ 302.4，但中间写成 `37.8*8=304` 后照抄 |

`252 = 3.5 × 12 × 8 × 0.75` —— 它把「打九折」理解成了 **75%**。

**这不是算术能力问题，是中文语用知识问题。** 而这种问题恰恰是中文用户最常问的：
打折、满减、几成、半价、包邮门槛……**小模型在这些词上集体失效**。

llama3.2 还额外暴露了一个毛病：输出里带 `<<12*3.5=42>>` 这种内部计算标记（Llama 3.2 的内置工具格式泄漏）。

## 2.5 MiniCPM3-4B：唯一在中文语义上站得住的竞品

| 题 | 结果 |
| --- | --- |
| 算术（九折 → 302.4） | ✅ **完全正确**，且推理过程干净（42元/箱 × 8 × 90% = 302.4） |
| 鸡兔同笼 | ✅ 23/12（过程有点绕，出现负数步骤，但答案对） |
| 代码 most_common | ✅ 正确（Counter + 取 max 后第一个） |
| 自动化脚本 | ✅ 基本正确（用 `find -mtime +7` 判定，有计数） |
| 摘要 ≤40 字 | ❌ 内容对，但 70 字，超了 |
| 数据聚合 | ❌ 香蕉算成 5（应为 6） |

**它是七个模型里唯一把「打九折」算对的。** 这验证了前面的判断：不是算术能力，是中文语用知识——而面壁的中文语料显然覆盖到了这类表达。

### 代价

| 项 | 数值 |
| --- | --- |
| 速度 | 28.5 tok/s @4k、21.8 @8k、15.1 @16k |
| 显存 | 4k→4.26GB(100%)、8k→5.51GB(83%)、16k→8.36GB(54%) |
| 上下文 | **KV 特别重**，8k 就开始溢出，16k 只剩一半在 GPU |
| 工具调用 | ❌ 这个 GGUF 只有 `completion` 能力，挂不了 tools |

**结论**：中文理解最好，但慢一半、上下文吃紧、不能当 B 档。适合"离线、短上下文、要中文准确"的场景。

## 3. 非 Qwen 阵营的真实状况

| 模型 | 上下文 | 中文 | 工具调用 | 实测结果 |
| --- | --- | --- | --- | --- |
| **Llama 3.2 3B**（Meta） | 128k | 弱 | ✅ | **1/6**，中文推理崩，有 `<<12*3.5=42>>` 格式泄漏 |
| **Gemma 3 4B**（Google） | 128k | 中上 | ❌ 无 | **3.5/6**，但没工具 + 冷启动 8.5s |
| **Phi-4-mini 3.8B**（微软） | 128k | 差 | ❌ 无 | **0~1/6**：算术 324、鸡兔自己绕晕、代码并列逻辑错、聚合值全错 |
| **MiniCPM3-4B**（面壁） | 32k | **强** | ❌ 此 GGUF 无 | **4/6**，唯一算对九折；但慢、KV 重 |
| Granite 3.3 2B（IBM） | 128k | 弱 | ✅ | 工具向，中文不适合 |
| SmolLM3 3B（HF） | 128k | 弱 | ✅ | 英文向 |

**判断**：Llama / Gemma / Phi 这三家的 3-4B 都是"英文优先"的模型，中文能力是附带品。真正能在中文上跟 Qwen 掰手腕的只有一个——**MiniCPM3-4B**（面壁智能），它在 Ollama 官方库没有，必须走 ModelScope 的 GGUF。

---

## 4. 那"竞品"到底有没有意义

**有，但不在"替代 Qwen"这个意义上。**

| 你的目的 | 建议 |
| --- | --- |
| 中文聊天 / 中文任务 | Qwen 系没有对手（在这个尺寸） |
| 英文代码 / 英文推理 | Llama 3.2 3B 够用且快（88 tok/s） |
| 想要**更快**的 A 档 | `qwen2.5:3b`（93 tok/s）能提速近一倍，代价是准确率 5/6 → 2/6 |
| 想要**更准** | 不是换模型，是加流程：多次采样 + `task-verify` 对账 |
| 想要更强 | 6GB 装不下；要 14B 可用至少需要 12~16GB 显存 |

## 5. 全部测完（含怎么复现 MiniCPM）

MiniCPM3-4B 官方库没有，是从 ModelScope 下 GGUF 后自建的：

```bash
curl -L -o ~/models/minicpm3-4b-q4.gguf \
  "https://modelscope.cn/models/OpenBMB/MiniCPM3-4B-gguf/resolve/master/minicpm3-4b-q4_k_m.gguf"
printf 'FROM /home/user/models/minicpm3-4b-q4.gguf\nPARAMETER num_ctx 32768\n' > /tmp/Modelfile.minicpm
ollama create minicpm3:4b -f /tmp/Modelfile.minicpm
node scripts/quality-tests.mjs minicpm3:4b
```

> ModelScope 是当前唯一稳定的下载源（官方 registry 时通时断，blob 在 `r2.cloudflarestorage.com`，DNS 一抖就断）。
> 实测 MiniCPM 的 KV 特别重：4k 才 100% GPU，8k 掉到 83%，16k 只剩 54%。

---

## 6. 一句话给你的答案

**这个级别"有竞品，但没有能替代 Qwen 的竞品"。**

- 综合最好：**qwen3.5:4b**（5/6，50 tok/s，工具可用）
- **中文语义最准：MiniCPM3-4B**（唯一算对"九折"），但慢一半、上下文吃紧、此 GGUF 挂不了工具
- 想要快：qwen2.5:3b（93 tok/s）换一半准确率
- 想要更强：6GB 装不下，换卡或上云
