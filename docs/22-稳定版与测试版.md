# 22 — 稳定版 / 测试版 双轨机制（现成实现）

> 2026-10-20 02:45 · 这套东西 openclaw 已经搭好了，本文是把它的用法和现状写清楚

## 0. 一句话

**`bridge/` = 稳定版（在跑），`bridge-test/` = 测试版，`scripts/promote-bridge.sh` 负责晋级，`rollback-bridge.sh` 负责退回。**

跟你说的"稳定版只含确认可用的部分，测试版慢慢加、再增量推进稳定版"完全对得上。

---

## 1. 两条轨道

| | 稳定版 | 测试版 |
| --- | --- | --- |
| 目录 | `bridge/` | `bridge-test/` |
| 谁在用 | **systemd 正在跑**（`ExecStart=.../bridge/qq-bridge.mjs`） | 手动跑 / SHADOW 模式 |
| 搜索 | `search.enabled = false` | `search.enabled = true` |
| 关系网 | `relations.enabled = false`、`nl = false` | 都 `true` |
| 角色 | 日常使用，**只放确认好用的** | 实验场，坏了不影响你 |

配置是**各自独立的**：`bridge/config.json` 与 `bridge-test/config.json`。改测试版的开关不会动到稳定版。

---

## 2. 测试版多出来的一个「影子模式」（这个很关键）

`bridge-test/qq-bridge.mjs` 里有一段：

```js
if (process.env.SHADOW === '1') {
  console.log('[shadow] ' + (isGroup ? 'group ' + data.group_id : 'private ' + data.user_id) + ' → ' + out.reply);
  return;
}
```

设置 `SHADOW=1` 后，机器人**照常读消息、照常推理、但一条都不发**，只把"本来会回什么"打到日志。

**用途**：在真实群里试搜索/关系网，不会刷屏、不会说错话。新功能先用影子跑几天，看日志里它想说什么，再决定要不要推到稳定版。

---

## 3. 晋级流程（`promote-bridge.sh`）

```
1. 检查 bridge-test 里 4 个文件是否齐全
2. node --check bridge-test/qq-bridge.mjs         ← 语法
3. node scripts/check-bridge-test-features.mjs    ← 关键功能不能丢
4. 备份稳定版 4 个文件 → releases/stable-<时间戳>/
5. 覆盖稳定版的 4 个文件
6. 再 --check 一次
7. systemctl --user restart qq-bridge
8. 等 3 秒，确认 is-active
9. 日志里必须出现 "OneBot 已连接"（15 秒内）
   —— 任一步失败 → 自动用备份还原 + 重启
```

**晋级只搬 4 个代码文件**：

```
qq-bridge.mjs   search.mjs   relations.mjs   relations-nl.mjs
```

**`config.json` 永远不搬** —— 脚本第一行注释就写着 `Stable config/data are NEVER overwritten`。
所以「测试版开了搜索」不会因为你晋级就把稳定版的搜索也打开。**功能开关仍然由你单独决定。**

---

## 4. 退回流程（`rollback-bridge.sh`）

```bash
scripts/rollback-bridge.sh              # 默认回退到最近一次快照
scripts/rollback-bridge.sh releases/stable-20261020-030000   # 指定某个快照
```

同样：语法检查 → 重启 → 验证 `OneBot 已连接`，失败就报错退出。

---

## 5. 当前状态

| 项 | 状态 |
| --- | --- |
| 稳定版 | 在跑，`search.enabled=false`、`relations.enabled=false` |
| 测试版 | 已存在，搜索与关系网都开着；多了 SHADOW 分支 |
| `releases/` | **还没有任何快照**（说明还没正式晋级过一次） |
| 代码差异 | 两版只差 `qq-bridge.mjs`（SHADOW 那段）和 `config.json`；`search.mjs`/`relations*.mjs` 完全一致 |

**这解释了"搜索有点 bug 就留在稳定版不动"** —— 稳定版直接把 `search.enabled` 关了，改动全部关在测试版里。这正是你要的做法。

## 6. 日常怎么用（三步）

### ① 在测试版上改

```bash
cd ~/.openclaw/workspace/projects/agent-dual-machine
# 改 bridge-test/ 里的文件
node scripts/check-bridge-test-features.mjs
```

### ② 影子跑一段（不打扰任何人）

```bash
cd bridge-test
SHADOW=1 node qq-bridge.mjs          # 注意：会与稳定版抢 OneBot 连接
```

> 若 OneBot 只允许一个连接，影子模式要先把稳定版停掉再跑，或者接受"谁先连上谁用"。
> 更稳的做法：改完先只跑 `node --check` + 特征检查，再用 `promote` 到稳定版观察日志（有自动回滚兜底）。

### ③ 确认没问题 → 晋级

```bash
scripts/promote-bridge.sh
```

失败会自动还原，不用你手动救。
