# 17 — 群关系网与称呼（在 123456789 里试验）

> 2026-10-19 · 实现：`bridge/relations.mjs` + 桥的两处挂点

## 0. 一句话

机器人**认得群里的人、叫得出称呼**，并且能攒出一张「谁常跟谁说话」的关系网。
只对配置里显式列出的群生效，**不存任何消息正文**。

---

## 1. 前置条件（三件）

| # | 条件 | 怎么确认 |
| --- | --- | --- |
| 1 | 机器人账号在这个群里 | 群里 @ 它，能回就说明在 |
| 2 | SnowLuma 会把这个群的**所有**消息上报（不只是 @ 它的） | 看日志有没有非 @ 消息的 `[search] skip(...)` 行 |
| 3 | 群号写进 `bridge/config.json` | 见下面第 2 节 |

> 关键点：**关系网靠"看所有人说话"建立**，所以必须能收到全量群消息。
> 如果 SnowLuma 只上报 @ 消息，关系网会几乎空着——那就只能靠 `@` 和回复连边。

---

## 2. 配置（已写好，改完热重载生效）

```json
"relations": {
  "enabled": true,
  "groups": { "123456789": {} },
  "addressReply": true
}
```

- `groups` 是**白名单**：没列出的群一律不记录，也不加称呼。
- `addressReply: true` → 回复时带称呼，例如「老王哥，在的～」。
- 想关掉某个群就把那一项删掉；想全关就 `enabled: false`（热重载，不用重启）。

---

## 3. 记什么、不记什么

| 记 | 不记 |
| --- | --- |
| QQ 号、群名片、昵称 | **消息正文**（一个字都不存） |
| 学到的别名 + 出现次数 | 图片/文件/表情内容 |
| 发言条数、最后活跃时间 | 私聊内容 |
| @ 关系、回复关系（谁→谁，次数） | 地理位置、IP |

- 文件：`bridge/.relations.json`，权限 **600**，只在 2060 本机。
- 上限：500 人 / 5000 条边 / 90 天不发言淡出。
- 一键清空：`node bridge/relations.mjs clear 123456789`

---

## 4. 称呼是怎么定的

**优先级：学到的别名（取最高频）> 群名片 > 昵称。**

别名从两种地方学：

| 来源 | 规则 | 例子 |
| --- | --- | --- |
| **显式声明（最可靠）** | `@某人` + `-这是X` / `-X`（半角 `-`、全角 `—` 都认） | `@老三 -这是大刘` → 老三别名 +「大刘」 |
| 别人怎么叫他 | 消息里 **@ 了唯一一个人**，且文本含「X哥/姐/叔/姨/总/老师/老板/大佬」→ 记在被 @ 的人身上 | `@老三 老王哥你来` → 老三的别名 +「老王哥」 |
| 自我介绍 | 文本含「我是 X」「叫我 X」「喊我 X」 | `叫我大刘` → 该用户别名 +「大刘」 |

**关于「先 @ 助手再 @ 别人」**：这类消息里有**两个 @**，之前会被判成「@ 了不止一个人」而放弃学习。
已修：学别名时**先剔除机器人自己**，剩下的 @ 目标只要唯一就照常学。

```
@助手 @老三 -这是大刘      ← 现在能正常学到「大刘」
@助手 @老王哥 你觉得呢      ← 也能学到「老王哥」
```

> 保守规则仍在：**@ 了多个真人**时不学（避免「张哥说得对」被错记到别人头上）。
> 裸 `-X` 只接受 2~6 个汉字，所以 `@某人 -100` 不会被当成名字。

---

## 5. 关系边怎么连

| 边 | 触发 |
| --- | --- |
| `mention` | 消息里 @ 了某人（@ 机器人自己不算） |
| `reply` | 消息是**回复**某条消息（用 `message_id → 发送者` 反查，窗口 10 分钟） |

边是**有向**的，带计数：`老王哥 → 小王 @1 回复1` 意思是老王哥 @ 过小王 1 次、回复过 1 次。

## 7. 在群里怎么试（三步剧本）

1. **让人叫你的外号**：让 A 发一条 `@B 老王哥 在吗`
   → 关系网里 B 会多出别名「老王哥」，A→B 多一条 @ 边。
2. **@ 机器人问一句**：`@机器人 你觉得老王哥说得对吗`
   → 机器人回你时会带称呼，例如「小王，…」
3. **回一条消息**：长按某人消息 → 回复 → 随便说句话
   → 关系网里多一条 `reply` 边（10 分钟内有效）。

然后跑一次 `summary`，应该能看到人和边都涨了。

---

## 8. 限制（别期待太高）

| 限制 | 说明 |
| --- | --- |
| 不跨群 | 每个群一张独立的图，同一个人在 A 群和 B 群的称呼互不影响 |
| 名片会覆盖 | 改群名片后，旧名片不保留（别名仍保留） |
| 无衰减权重 | 只有累计计数，没有"最近更活跃权重更高"——以后可以加 |
| 学不到间接称呼 | 只能从 @ + 后缀词、自我介绍里学；"老王"这种昵称学不到 |
| 回复边依赖 message_id | 有的适配器不回传 reply 段，那就只剩 @ 边 |

---

## 9. 回滚

```bash
# 只关称呼，继续记关系
"addressReply": false

# 全关（连记录也不做）
"relations": { "enabled": false }

# 连数据一起清掉
node bridge/relations.mjs clear 123456789
```

改完 config 热重载即生效；`enabled: false` 后 `observe()` 完全不会被调用。

---

## 10. 为什么这样设计（取舍说明）

- **不存正文**：关系网只需要"谁跟谁有互动"，不需要"说了什么"。存正文会让这个功能变成一个隐私雷。
- **白名单**：默认全关，只在你点名的群里开 —— 避免"装了个机器人，全群聊天记录都被分析"。
- **确定性规则**：别名和边都用可解释的规则学，不用模型判断（4B 做这种归纳不可靠，还会把名字搞错）。
- **可回滚**：一个 `enabled: false` 就能停，不留后台任务。
