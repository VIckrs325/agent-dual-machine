# 12 — 联网搜索接入方案（实测版）

> 2026-10-18 · 全部数据来自 2060 本机实测，不是估算。

## 0. 一句话结论

**QQ 聊天链路用「桥内确定性检索」，不用 skills，也不用 DeepSeek 搜索 API。**

- **skills 路线**：依附 agent 运行时。OpenClaw 基础提示约 10.9k token，6GB 卡上 prefill 就要 6~7 秒 —— 桥现在是 0.3~2 秒，接进去等于报废。
- **DeepSeek 搜索 API**：是**服务端工具**（模型自己决定搜不搜），不是"给我结果"的接口。实测 `v4-flash` 根本不触发搜索，`v4-pro` 触发 3 次、耗时 15.7 秒、输入 6.1k token，且返回的是它自己写的综述而非可引用的片段。
- **桥内检索**：代码决定搜不搜、搜什么、取几条，延迟可控、结果可引用、失败能降级。

B 档（DSH / OpenClaw 里做慢任务）反而是唯一适合用 skill / DS 搜索的地方。

---

## 1. 五条路线实测对比

| 路线 | 最小延迟 | 谁决定"搜不搜" | 结果形态 | 判定 |
| --- | --- | --- | --- | --- |
| **桥内确定性检索**（已实现） | **0.66 ~ 2.0s** | 代码规则 | 标题 + 摘要 + URL | ✅ A/B 档主力 |
| DS `web_search` + `v4-pro` | **15.7s** | 模型 | 已写好的综述 + 来源 | ⚠️ 仅 B 档兜底 |
| DS `web_search` + `v4-flash` | 2.0s | 模型 | **没搜**，凭记忆答（把日期说成 2026-05-07） | ❌ 不可用 |
| OpenClaw / DSH 的 skill | 基础 6~7s + 工具耗时 | 模型 | 取决于 skill | ⚠️ 仅 B 档 |
| Bocha / Tavily API | **0.3~0.6s**（待 key 验证） | 代码 | 干净摘要（为 LLM 设计） | ✅ 推荐升级 |

DS 那条的原始数据：

```
### v4-flash + web_search_2025_08_26 | 1961ms
  output types: ['reasoning', 'message']      ← 没有 web_search_call
  input_tokens: 35   output: 151

### v4-pro + web_search_2025_08_26 | 15668ms
  output types: ['reasoning','web_search_call','reasoning','web_search_call','web_search_call','reasoning','message']
  input_tokens: 6104  output: 790
  URL: weather.com.cn / weather.com（真实来源，但正文是英文综述）
```

**两个附加发现**：① 工具类型必须写版本化名字 `web_search_2025_08_26`，写 `web_search` 不报错但也不搜；② 同样参数下 flash 和 pro 的行为完全不同 —— 这条路不可预测。

## 2. 搜索源实测（从 2060 直连）

| 源 | 延迟 | 拿到几条 | 备注 |
| --- | --- | --- | --- |

## 3. 已实现：`bridge/search.mjs`

零依赖，和桥同目录，桥启动时自动加载。

### 3.1 触发规则（代码判断，可预测）

```js
显式指令：搜一下|搜搜|帮我查|查一下|查查|搜索一下|网上查|搜个   → 直接搜
时效 + 疑问：最新|今天|现在|价格|股价|天气|新闻|比分 … 且 吗|多少|什么|怎么|谁 … → 搜
代码类豁免：命中 代码|函数|报错|python|sql|正则 → 不搜（本地模型更擅长）
```

### 3.2 检索词清洗（这条最值钱）

同一句话，只差「帮我查一下」四个字：

| 检索词 | 返回的站点 |
| --- | --- |
| `帮我查一下 qwen3.5 是什么时候发布的` | jingyan.baidu.com、zhihu.com/question/64258496 ❌ |
| `qwen3.5 是什么时候发布的` | **qwen.ai/blog、github.com/QwenLM、huggingface.co** ✅ |

所以 `buildQuery()` 会剥掉「帮我 / 请 / 查一下 / 搜一下 / 请问」这类词，并去掉句末标点。**没有这一步，搜索等于白接。**

### 3.3 注入与引用

检索结果拼成编号块塞进 user 消息，system 追加约束：

```
下面附有联网检索到的资料。优先依据资料回答，并在句末标注来源编号如[1]；
资料没覆盖到就直说"没查到"，不要编造具体数字、时间、人名。
```

实测效果（模型确实照做）：

```
[llm+search] 2104ms | bing 659ms 3条
→ "不确定。资料仅提及 Qwen3 的发布，未包含 Qwen3.5 的具体发布时间 [1][2][3]。"

[llm+search] 3285ms | bing 2048ms 3条
→ "没查到。资料仅显示有北京今日及多日预报信息，未包含具体温度 [1][2][3]。"
```

**这两条都不是失败**——资料确实没有答案，模型选择"明说没查到"而不是编造，这正是要的行为。

### 3.4 成本控制

| 手段 | 效果 |
| --- | --- |
| `maxResults: 3` + `snippetChars: 240` | 上下文约 1.2k 字符 ≈ 800 token ≈ **+0.5s prefill** |
| 5 分钟查询缓存 | 重复问题省掉 0.6~2s |
| 6s 超时 + 失败降级 | 搜不到就正常聊，不阻塞 |
| 搜索回答放宽到 160 字 / `numPredict×2` | 带引用的回答需要更长 |

## 4. 时间账（实测）

| 场景 | 总延迟 |
| --- | --- |
| 规则命中（你好 / 谢谢） | **0ms** |
| 普通聊天（不触发搜索） | **0.5~0.6s** |
| 问答 + 搜索命中快源 | **2.1s**（bing 659ms） |
| 问答 + 搜索命中慢源 | **3.3s**（bing 2048ms） |
| 同问题再问（命中缓存） | −0.6~2.0s |

对 A 档来说 2~3 秒是可感知的慢，所以**只在必要时搜**；真要更快只能换付费 API（0.3~0.6s），总延迟能压到 1.2s 左右。

## 5. 已知局限（别指望它什么都能查）

| 类型 | 表现 | 建议 |
| --- | --- | --- |
| **结构化数据**（天气 / 股价 / 比分 / 汇率） | 摘要全是 SEO 落地页，正文是表格抓不出 | 接专用 API，或让 OpenClaw 用它的 `weather` skill |
| 需要多跳推理 | 4B 整合能力有限 | B 档路由云端 |
| 反爬 | Bing 随时可能改结构 | 备用 `provider: "ddg"` |
| 免费源 | 无 SLA、可能限流 | 生产建议 Bocha |

`depth: "read"` 这一档我实现了（抓正文 + 按 2-gram 抽相关句），但对**表格类页面无效**：抓 weather.com.cn 抽出来全是新闻标题，还多花 3 秒。所以默认关闭，只在文章类页面有收益时手动开。

## 6. 配置项

`bridge/config.json`：

```json
"search": {
  "enabled": true,
  "provider": "bing",        // bing | ddg | bocha | tavily
  "maxResults": 3,
  "snippetChars": 240,
  "timeoutMs": 6000,
  "cacheTtlMs": 300000,
  "depth": "snippet",        // snippet=只用摘要 | read=再抓正文
  "autoRead": false
},
"searchMaxChars": 160
```

改完**自动热重载**，不用重启桥。付费源：

```bash
# 写进主控端的 vault（项目目录之外），再推送到算力端的 tmpfs
echo 'BOCHA_API_KEY=sk-xxx' >> ~/.secrets/qq-bridge.env   # 或 TAVILY_API_KEY
node scripts/secrets.mjs push --host user@host
# provider 改成 bocha 即可
```

## 7. 升级路径（按性价比）

1. **换 Bocha**（¥ 级成本）：0.3~0.6s + 干净摘要，一步解决"SEO 垃圾"和慢两个问题。
2. **结构化数据接专用源**：天气/股价这类别走通用搜索。
3. **B 档加 DS 深搜**：在 DSH 里调 `deepseek-v4-pro` + `web_search_2025_08_26`，当"调研兜底"，15 秒能接受。
4. **不做的事**：别把 OpenClaw 插进 QQ 链路来获得"skill 搜索"，延迟会从 2s 变 9s。

## 9. v2 升级（2026-10-19）

### 为什么升

线上实测：**73 条回复里只搜了 1 次（1.4%）**。日志里还有一条「我无法获取实时天气数据」，说明天气问题压根没触发检索。

根因三条，都在触发与质量环节，不在搜索源：

1. **触发条件要求 `时效词 && 疑问词` 双命中** →「今天美元汇率」「DeepSeek 是什么公司」「周杰伦是谁」全被跳过。
2. **摘要质量没有门槛** → Bing 对某些查询返回百度经验/黄历/百科，直接喂给 4B 就会答"没查到"。
3. **检索词带虚词** → `北京今天天气怎么样` 会让 Bing 返回「北京市百科」；去掉"怎么样"才是天气预报页。

### 改了什么

| 项 | v1 | v2 |
| --- | --- | --- |
| 触发 | `fresh && ask` | 三档：`force`（显式指令 / 时效+疑问）、`attempt`（时效词 / 实体查询，超时 3.5s）、`skip`（代码类 / 无信号） |
| 检索词 | 只去指令词 | 再剥句尾虚词（怎么样/呢/吗）、`有什么`、句尾 `多少/多久/多少钱` |
| 质量门槛 | 无 | 摘要 ≥50 字 + 噪声域黑名单 + 同域去重 + 相关性 2-gram 命中 |
| 失败处理 | 直接返回空 | 主源无有效结果 → 降级 `ddg` → 仍无 → 不注入（并记日志） |
| 缓存 | 只缓存成功 | 失败结果负缓存 60s，避免反复慢查询 |
| 观测 | 只打成功行 | `[search] skip(reason)` / `[search] 未注入 reason=...` / 命中行带 `mode/reason raw/kept provider ms` |

### 实测对比

触发分布（16 条典型问句）：

| 版本 | 会搜 | 不搜 |
| --- | --- | --- |
| v1 | 4 | 12（含「今天美元汇率」「周杰伦是谁」） |
| v2 | 10（force 6 + attempt 4） | 6（3 条闲聊、2 条代码、1 条定义题「什么是 API」） |

检索词清洗效果：

| 原句 | v1 | v2 |
| --- | --- | --- |
| 北京今天天气怎么样？ | `北京今天天气怎么样` → 北京市百科 ❌ | `北京今天天气` → 天气预报页 ✅ |
| iPhone 17 多少钱 | 不搜 ❌ | `iPhone 17` → Apple 官网 / Wikipedia ✅ |
| 最近有什么AI新闻 | `最近有什么AI新闻` → 今日热榜 ⚠️ | `最近AI新闻` → 今日热榜 ⚠️ |

线上自测（重启后）：

```
[search] skip(no_signal) "用一句话解释什么是 API。"
 4170ms [llm] ...                    ← 未搜，正常回答
[search] skip(code) "Python 里怎么反转列表？"
  450ms [llm] ...                    ← 未搜，0.45s
 2864ms [llm+search] force/fresh+ask bing 2075ms raw=3 kept=3 q="北京今天天气"
   → "资料中仅显示连续晴天，未提供具体气温等详细数据。[2]"
 1200ms [llm+search] force/explicit bing 522ms raw=3 q="qwen3.5 是什么时候发布的"
   → "没查到 Qwen3.5 的发布时间。[1][2][3]"
```

最后两条的要点：**它们都在引用资料后说"没有具体数据"**，而不是硬编一个温度 —— 这是要的行为。

### 还解决不了的

**实时结构化数据**（今日气温 / 股价 / 比分）：通用搜索给的是 SEO 落地页，摘要里没有数值。过滤修不了，要接专用 API：

| 数据 | 建议源 |
| --- | --- |
| 天气 | `wttr.in`、Open-Meteo（免费无 key） |
| 股价 / 汇率 | 交易所/券商 API，或现成行情 MCP |

现在遇到这类问题会明确回"没查到/未提供数据"，不会编 —— 有意的降级。

### 回滚

```bash
systemctl --user restart qq-bridge                 # 重载新代码
# 彻底关搜索：config.json 里 search.enabled=false（热重载生效）
```
