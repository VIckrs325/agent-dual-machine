## 1. 现在的阻塞：系统 DNS 挂了

想试新模型，第一步 `ollama pull` 全部失败。查下来不是模型库的问题：

| 检查 | 结果 |
| --- | --- |
| 网关 `192.168.1.1` | ✅ ping 4ms |
| 公网 IP `223.5.5.5` | ✅ ping 9ms（ICMP 通） |
| 系统解析 `getent hosts www.bing.com` | ❌ FAIL |
| `resolvectl` 当前 DNS | `192.168.1.1`（路由器），但**不回应查询** |
| 外网 UDP/TCP 53 | ❌ 不通（校园网 `AMA_CDUT_5G` 基本封外部 DNS） |
| DoH `https://223.5.5.5/resolve` | ✅ 可用（走 443） |
| `www.baidu.com` 用 DoH IP 直连 | ✅ 200 / 0.2s |
| `www.bing.com` 用 DoH IP 直连 | ✅ 302 / 0.2s |
| **`registry.ollama.ai`（Cloudflare）** | ❌ **即使知道 IP 也连不上**（8s 超时） |
| `www.modelscope.cn` | ✅ 302 / 0.24s |
| `hf-mirror.com` | ❌ 超时 |

**两个独立问题**：
1. **DNS 服务失效**（路由器不转发）→ 影响搜索、任何域名访问
2. **Ollama 官方 registry 不可达**（Cloudflare IP 被拦）→ 即使 DNS 修好，`ollama pull` 也可能失败

> 顺带提醒：今天下午"搜索时好时坏"，很可能有一部分就是这个 DNS 开始劣化造成的，不全是搜索逻辑问题。

### 修法（都需要一次 sudo 或换网络）

```bash
# 方案 A：重启解析器，让它重新拿上游
sudo systemctl restart systemd-resolved
resolvectl flush-caches
getent hosts www.bing.com        # 验收

# 方案 B：手动指定 DNS（校园网封 53 的话可能无效）
sudo resolvectl dns wlp61s0 223.5.5.5 119.29.29.29
sudo resolvectl flush-caches

# 方案 C（最省事）：手机开热点，笔记本连热点
```

DNS 修好后，**Ollama 官方源仍可能不通**，那就走 ModelScope：

```bash
# ModelScope 可达；下 GGUF 后用 Modelfile 建
curl -L -o /tmp/qwen2.5-3b-q4.gguf \
  "https://modelscope.cn/models/Qwen/Qwen2.5-3B-Instruct-GGUF/resolve/master/qwen2.5-3b-instruct-q4_k_m.gguf"
printf 'FROM /tmp/qwen2.5-3b-q4.gguf\nPARAMETER num_ctx 32768\n' > /tmp/Modelfile
ollama create qwen2.5:3b-local -f /tmp/Modelfile
```

## 2. 候选清单（网络通了就照这个试）

显存 6GB、要 32k 上下文、要中文、可能还要工具调用 —— 按这个筛出来的：

| 模型 | 体积(Q4) | 上下文 | 中文 | 工具调用 | 适合 |
| --- | --- | --- | --- | --- | --- |
| **qwen2.5:3b** | ~1.9GB | 32k | 强 | ✅ Ollama 支持 | **A 档首选**（快、稳、不思考） |
| **qwen3:4b-instruct-2507** | ~2.5GB | 32k+ | 强 | ✅ | **A+B 档最佳候选**（非思考 + 指令遵循好） |
| gemma3:4b | ~3.3GB | 128k(默认8k) | 中上 | ⚠️ 弱 | 中文语感 / 长文对比 |
| llama3.2:3b | ~2.0GB | 128k | 一般 | ✅ | **速度上限参考**（极快，中文弱） |
| phi4-mini (3.8B) | ~2.5GB | 128k | 差 | ✅ | 英文推理，中文不建议 |
| minicpm3-4b / hunyuan-4b | ~2.5GB | 32k | 强 | 视版本 | 官方库多半没有，需 ModelScope GGUF |

**我的建议顺序**：`qwen3:4b-instruct-2507` → `qwen2.5:3b` → `llama3.2:3b`（当速度标尺）。
gemma3 放最后，因为它的工具调用弱，对 B 档没帮助。

## 3.5 实测结果（2026-10-20 01:20，网络恢复后）

先说明：`qwen3:4b-instruct-2507` 这个 tag **在官方库不存在**（报 `file does not exist`）；
`llama3.2:3b` / `qwen3.5:2b` 下载中途又遇到 DNS 抖动（blob 在 `r2.cloudflarestorage.com` 解析超时），没下完。
实际测到的是下面四个（后两个是你手动拉下来的）。

### 统一评测（`bench-models.mjs`，32k ctx）

| 模型 | decode | 首字预填 | ≤50字 | 退货率(应为25%) | 工具调用 | 显存 |
| --- | --- | --- | --- | --- | --- | --- |
| **`qwen2.5:3b`** | **93.0 tok/s** | 20ms | 28 字 ✅ | ✅ 25% | ✅ | 2.27GB / 100% |
| `Qwopus3.5-4B-Coder-MTP` | 59.3 tok/s | 132ms | 40 字 ✅ | ❌ **75%（连测 3 次都是）** | ✅ | 3.07GB / 100% |
| `qwen3.5:4b`（现役） | 50.6 tok/s | 123ms | 37 字 ✅ | ✅ 25% | ✅ | 3.24GB / 100% |
| `locooperator:4b-q8_0` | 15.4 tok/s | 165ms | 32 字 ✅ | ✅ 25% | ✅ | 5.04GB / **90%** |

### A 档口径（用桥的真实 system prompt + 5 个日常问题）

| 模型 | 平均延迟 | 最长回复 | 超 50 字 | 观感 |
| --- | --- | --- | --- | --- |
| `qwen2.5:3b` | **725ms** | 16 字 | 0/5 | 最简练，略冷（"休息一下就好了"） |
| `Qwopus3.5-4B-Coder-MTP` | 1034ms | 33 字 | 0/5 | 语感最好（"抱抱你，快去睡一觉"） |
| `qwen3.5:4b` | 1051ms | 32 字 | 0/5 | 稳，信息量适中 |

### 各模型的问题

| 模型 | 好 | 坏 |
| --- | --- | --- |
| `qwen2.5:3b` | **速度几乎翻倍**（93 vs 50），A 档延迟 725ms，回答最干净 | 偏冷淡、信息量少；2024 年的模型，知识截止早 |
| `Qwopus（MTP）` | 中文语感最好、代码正确（`s == s[::-1]`）、MTP 提速约 18%、标称 64k 上下文 | **退货率题稳定算反**（把未退货率 75% 当答案）—— 需要"理解题意"的计算类问题不可信 |
| `locooperator:4b-q8_0` | Q8 精度，回答正常 | 15 tok/s 太慢；5GB 还只 90% GPU；不适合交互 |

### 结论

1. **A 档最值得试的是 `qwen2.5:3b`**：速度翻倍、延迟降 30%，日常问答没短板。代价是语气偏平、知识旧。
2. **B 档保持 `qwen3.5:4b`**：工具调用 + 32k 稳定 + 算术正确。`Qwopus` 虽有 64k 潜力，但"静默算错"这条在任务场景不能接受。
3. **`locooperator` 不建议**：Q8 在 6GB 上换来的精度，远不值 15 tok/s。
4. 想用 `Qwopus` 的话，只放在"闲聊 + 写代码"，别让它做任何数字推理。

## 4. 评测方法（已经脚本化）

```bash
cd ~/.openclaw/workspace/projects/agent-dual-machine
node scripts/bench-models.mjs qwen2.5:3b qwen3:4b-instruct-2507 gemma3:4b
```

每个模型测五项：

1. **生成速度**（tok/s，来自 `eval_count/eval_duration`）
2. **首字延迟**（`prompt_eval_duration`）—— A 档体感主要由它决定
3. **指令遵守**：「用不超过 50 字解释 API」看字数是否守住
4. **算术/事实**：退货率题（12 单退 3），看会不会给 25%
5. **工具调用**：给一个 `get_weather` 工具，问天气，看是否返回 `tool_calls`

外加 `ollama ps` 里的**显存占比**，确认没有溢出到 CPU（溢出会慢 5~10 倍）。

## 5. 换模型时要注意的

- `OLLAMA_MAX_LOADED_MODELS=1` → 换模型会把上一个踢出显存，测完记得把 `qwen3.5:4b-chat` 重新拉热，否则 A 档第一条会慢 3~5 秒
- `OLLAMA_KEEP_ALIVE=-1` → 加载后就常驻，别同时开两个大模型（14B IQ2 是 5.3GB，会和 4B 抢显存）
- 新模型测完如果不如现役，**不用急着删** —— 磁盘还有 48G，留着做对照
